# Проверки качества F01

`pnpm typecheck` проверяет frontend TypeScript; `pnpm lint` запускает ESLint для `src/`, `tests/`, `scripts/` и корневых TS/JS-конфигураций; `pnpm format:check` проверяет Prettier для кода и новых конфигураций; `pnpm lint:styles` проверяет CSS в `src/`. `pnpm test` выполняет существующие Node-тесты и новые Vitest-тесты. `pnpm build` проверяет сборку. CI повторяет эти команды без БД и секретов.

Исторический код не переформатирован в F01. `scripts/quality/quality-baseline.json` хранит SHA-256 нормализованного по LF содержимого старых файлов. Для Prettier неизменённые старые файлы пропускаются, а новый или изменённый файл проверяется полностью. Для ESLint baseline содержит только 10 файлов с обнаруженными до F01 нарушениями; остальные старые файлы проверяются при каждом прогоне. Если содержимое файла из baseline изменится, исключение автоматически перестанет действовать. Нельзя обновлять хеши, чтобы скрыть новую ошибку; после исправления следует удалить запись соответствующего файла из baseline. Stylelint проверяет все CSS-файлы; только для существующего `src/index.css` пять правил современного написания цвета, кавычек семейства шрифтов и `@import` отключены адресным override, чтобы не переформатировать старый стиль.

Компонентные тесты используют Vitest, jsdom и React Testing Library. Node-тесты сохраняются до осмысленной миграции. Playwright и Deno относятся к F02. Проверка `pnpm release:check` предназначена для опубликованного релиза: пока ветка содержит версию 1.1.x, а пользовательская заметка `currentRelease` описывает опубликованный 1.0.0, её ожидаемое несовпадение не блокирует промежуточные коммиты.

F02 добавляет `pnpm test:e2e`: Playwright поднимает локальный Vite-сервер с фиктивными env, подставляет Telegram/API и блокирует неожиданные внешние запросы. `pnpm test:edge` запускает Deno-тесты чистых Edge helpers без сети и БД; на Windows использует проверенный локальный `tools/deno/deno.exe`, в CI — установленный Deno. `tools/` игнорируется Git. CI запускает обе проверки, но не запускает БД.

Проверку `supabase/tests/database/f02_rls.sql` в текущем локальном Supabase выполняет только владелец через `scripts/quality/run-local-db-check.ps1`. Скрипт проверяет project ID и адрес локальной БД до запуска pgTAP. Supabase CLI выполняет каждый тест в откатываемой транзакции; fixture синтетический, а общий reset не используется. Если local stack остановлен или адрес иной, проверка останавливается. Результат этой проверки записывается в F02 `verification.md` после получения вывода владельца.
