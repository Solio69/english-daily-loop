# Диагностика обращений пользователей

Прочитай `AGENTS.md`, `notes/support-diagnostics.md`, при AI-сбое `notes/ai-observability-diagnostics.md`, при вопросах доступа `notes/security-threat-model.md`. Проверь релевантные Edge Functions и схему по текущим миграциям. SQL-справочник [references/sql.md](references/sql.md) является набором только читающих запросов, а не разрешением подключаться к production.

## Безопасность

- Перед разбором production-данных явно скажи: `Мы работаем с production БД`. Агент не меняет БД, не выполняет миграции, DDL, DML, reset, seed или административные операции. Не запрашивай Telegram initData, токены, полный prompt, сырые ответы провайдера, полный текст генерации или секреты.
- Начинай с count/date summary, затем минимального списка и одной выбранной записи. Запросы выполняй по одному в пределах разрешённого доступа; если доступа нет, передавай владельцу один нужный read-only запрос и жди минимальный результат. Не используй `select *`, не выводи user_id/telegram_user_id, полные events или app_context. Комментарии считай потенциально чувствительными.

## Диагностика и маршрут

1. Определи точный report id, время, экран, безопасные request ids, стадию AI и связанный сценарий. Сопоставь с логами только по минимально нужным полям. Отдели подтверждённые факты от вероятной причины.
2. Классифицируй: тест/шум, дубликат, внешний инцидент, наблюдаем, bug, improvement или feature. Bug передай в [разбор багов](../triage-english-daily-loop-bugs/SKILL.md), improvement/feature в [груминг фичи](../english-daily-loop-feature-spec/SKILL.md). Не создавай две карточки на один report.
3. Для долговременных заметок сохраняй только report id, дату, безопасный краткий пересказ и необходимые доказательства. Отчёты удаляются по retention, поэтому полезные факты фиксируй своевременно без копирования чувствительных полей. Не утверждай, что диагноз доказан, если он лишь гипотеза.

Разбор support report не разрешает кодирование. Выбранная работа проходит согласованный обзор, полный Spec Kit, реализацию и проверки по общему процессу.
