# Подготовка и согласование фичи

Этот скилл сохраняет полезный подход прежнего feature-spec. Общие правила груминга всех задач: `D:\anastasiaStorage\Проекты\English daily loop\_agents\rules\Груминг задач English Daily Loop.md`. Жизненный цикл разработки: `D:\anastasiaStorage\Проекты\English daily loop\_work\release-1.1-refactor\SDD workflow English Daily Loop.md`. Прочитай оба документа перед грумингом фичи. Технические спецификации после согласования находятся в `specs/NNN-slug/`; их пишут `speckit-*` скиллы.

## Порядок

1. Прочитай `AGENTS.md`, `GIT_POLICY.md`, конституцию, релевантные notes, [дизайн-систему](../../../docs/DESIGN_SYSTEM.md) для UI, код, миграции и тесты. Git анализируй только чтением. Подтверждай факты актуальным репозиторием; не переносить старые версии поведения на веру.
2. После исследования покажи минимум два жизнеспособных варианта реализации: что меняется технически, плюсы, минусы, риски, стоимость сопровождения и рекомендация. Если разумен один вариант, объясни почему. Серверные операции и данные объясняй пользователю простыми словами. Существенный выбор оставь пользователю.
3. Создай или обнови один компактный обзор фичи в `D:\anastasiaStorage\Проекты\English daily loop\_work` по [шаблону](references/feature-template.md): результат, границы, выбранное решение, шаги, проверки и открытые вопросы. Не создавай вторую очередь в репозитории и не смешивай обзор с полными spec/plan/tasks. Решённые вопросы вписывай в целевое решение; историю «было → стало» не веди.
4. Свяжи наблюдаемые критерии с автоматическими проверками или подробными ручными сценариями. Применимое руководство: [ручные проверки](../../references/manual-testing-guide.md). Короткий сценарий владельца понятен без чтения технического плана; подробные сценарии содержат среду, предусловия, действия и ожидаемые результаты. Отметки ручного выполнения ставит пользователь.
5. Согласование всего обзора и назначенная пользователем ветка открывают полный Spec Kit и реализацию без повторного обязательного допуска. Ответ на один вопрос не означает согласование всей фичи. Новое существенное решение возвращай пользователю до затронутой реализации.

Во время груминга не меняй продуктовый код, БД, Git-состояние и не устанавливай пакеты. После согласования применяй `speckit-constitution`, `speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-checklist`, `speckit-tasks`, `speckit-analyze`, `speckit-implement` в указанном порядке с технической доработкой и повторным анализом по необходимости.
