# Повторение слов

## 1) Область документа

Документ фиксирует текущую реализацию повторения подтвержденных словарных карточек:
бизнес-алгоритм, дневную очередь, завершение плана, серверные операции и UI.

Подготовка и подтверждение AI-карточек описаны в
`notes/vocabulary-save-flow.md`.

## 2) Product rules

- После подтверждения карточка получает `card_status = ready` и
  `status = not_started` и сразу доступна в очереди текущего дня.
- Обязательная очередь формируется без дневного cap: план завершен, когда повторены
  все карточки, обязательные на текущую дату.
- Дата дня и проверка `last_reviewed_at` считаются по `Europe/Moscow`.
- После завершения обязательной очереди создается дневной completion-marker.
- Карточки, подтвержденные после завершения дня, доступны как дополнительные новые
  слова, но не открывают завершенный план заново.
- Если обязательных карточек нет, сервер фиксирует завершенный день с
  `reviewed_count = 0`.
- `learned`-карточки остаются в БД и словаре, но не попадают в очередь повторения.
- Повторное добавление `learned`-слова сбрасывает его в `not_started` и очищает
  интервалы и статистику повторения.
- Merge pending-дубликата с существующим `active`-словом сохраняет его текущий шаг и
  статистику.

## 3) Алгоритм

### Статусы карточки

```txt
not_started — подтвержденная карточка доступна в очереди, но еще не получила интервал
active — слово участвует в алгоритме повторения
learned — слово считается изученным
```

### Шкала повторения

```txt
1 день
3 дня
7 дней
14 дней
1 месяц
2 месяца
3 месяца
4 месяца
5 месяцев
6 месяцев
изучено
```

`изучено` — финальное состояние. После перехода в него карточка получает
`status = learned`.

### Вход в алгоритм

Карточка `not_started` сразу доступна в очереди. После первого ответа она получает
`status = active` и выбранный интервал:

```txt
not_started → active
шаг: выбранный интервал
```

### Действия пользователя

На каждом шаге пользователь выбирает один из четырех вариантов:

```txt
Не помню
текущий шаг
следующий шаг
шаг через один
```

Правила:

```txt
Не помню → 1 день
текущий шаг → текущий шаг
следующий шаг → следующий шаг
шаг через один → шаг через один
```

Если выбранный переход выходит за пределы шкалы, карточка переходит в `learned`.

### Дата следующего повторения

```txt
nextReviewDate = today + выбранный интервал
```

Новая дата всегда считается от текущей даты, а не от старой плановой даты. Для
`learned`-карточки `nextReviewDate = null`.

## 4) Дневная очередь

Карточка обязательна для повторения, если:

```txt
card_status = ready
status = not_started
или
status = active и nextReviewDate <= today
```

Порядок очереди:

```txt
новые → просроченные → назначенные на сегодня
```

Просроченная карточка остается доступной. Completion-marker в
`public.user_daily_vocabulary_review_completions` фиксирует выполненный план на дату.
После его создания новые `not_started`-карточки возвращаются как optional.

## 5) DB model

Поля повторения в `public.user_vocabulary_words`:

- `status`;
- `review_step`;
- `next_review_date`;
- `last_reviewed_at`;
- `review_count`;
- `forgot_count`;
- `same_step_count`;
- `next_step_count`;
- `jump_step_count`;
- `learned_at`.

Дневное завершение хранит таблица
`public.user_daily_vocabulary_review_completions`:

- `user_id`;
- `review_date`;
- `completed_at`;
- `reviewed_count`;
- уникальность `(user_id, review_date)`.

Таблица и server-only RPC закрыты для `anon` и `authenticated`; доступ оставлен
только `service_role`.

Миграции:

- `supabase/migrations/20260618120000_add_vocabulary_review_flow.sql`;
- `supabase/migrations/20260622120000_harden_vocabulary_review_state.sql`.

## 6) Transactional RPC

`public.review_vocabulary_word(...)`:

- берет transaction-level advisory lock по пользователю и дате;
- блокирует выбранную карточку через `FOR UPDATE`;
- проверяет владельца, `card_status`, статус и действие;
- атомарно обновляет шаг, следующую дату и счетчики;
- после последней обязательной карточки записывает дневной completion-marker.

`public.get_or_create_vocabulary_review_state(...)`:

- использует тот же advisory lock;
- одним серверным snapshot считает точные количества карточек;
- выбирает следующую карточку по правилам алгоритма;
- создает completion-marker, если обязательная очередь пуста;
- после завершения дня возвращает новые карточки как optional;
- не ограничивает расчет размером клиентской выборки.

## 7) Edge Functions

`get-vocabulary-review-state`:

- валидирует Telegram `initData`;
- получает текущего пользователя;
- вызывает `get_or_create_vocabulary_review_state` с московской датой;
- возвращает progress, dictionary actions и текущую карточку с четырьмя действиями.

`review-vocabulary-word`:

- валидирует `wordId` и action;
- вызывает `review_vocabulary_word` с московской датой;
- возвращает новый статус, шаг, дату и признак обязательной карточки.

Общие server helpers:

- `supabase/functions/_shared/vocabulary-review.ts`;
- `supabase/functions/_shared/vocabulary-review-state.ts`;
- `supabase/functions/_shared/home-progress.ts`.

## 8) Frontend

Экран `Слова`: `src/screens/VocabularyScreen.tsx`.

Компоненты:

- `VocabularyReviewProgressCard` — дневной счетчик и progress bar;
- `VocabularyDictionaryActionsNotice` — переход в словарь при наличии pending или
  needs-approval карточек;
- `VocabularyReviewWordCard` — закрытая и раскрытая карточка с действиями.

Закрытая карточка показывает слово, заблокированные секции и CTA
`Показать перевод`. После раскрытия переиспользуются словарные компоненты части речи,
форм глагола и примеров. Целевое слово в примерах подсвечивается теплым акцентом.

После раскрытия карточка автоматически прокручивается так, чтобы нижние действия не
скрывались за навигацией. После ответа экран запрашивает следующий серверный snapshot.

## 9) Home progress

Daily lesson состоит из двух последовательных шагов:

1. `reading`;
2. `vocabulary`.

После завершения чтения урок остается `in_progress`, пока обязательное повторение не
получит статус `completed`. `homeProgress.review` содержит `status`, `dueCount` и
`reviewedTodayCount`.

## 10) Dev tools и проверки

Локальные действия:

- `reset_vocabulary_review_progress`;
- `make_vocabulary_reviews_due_today`;
- `clear_today_vocabulary_review_completion`.

Они доступны только при клиентском `VITE_DEV_TOOLS_ENABLED="true"` и серверном
`DEV_TOOLS_ENABLED="true"`.

Unit-тесты проверяют начальные/финальные подписи интервалов, навигационный стек и
русские формы счетчиков. Запуск: `pnpm test`.
