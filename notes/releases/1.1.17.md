# Production-обновление 1.1.17

**Статус:** локальные проверки пройдены; владелица явно приняла ограничение контраста для 1.1.17. Production 1.0.0 обслуживает реальных пользователей. PR, merge, deploy, smoke, tag и GitHub Release ещё не подтверждены.
**Целевая дата:** 2026-11-16. Если выпуск переносится, дата в currentRelease и CHANGELOG меняется до release commit и повторяется release:check.
**Обзор F17:** specs/018-f17-release-readiness/ и рабочий обзор владельца в Obsidian.

## Состав

Версия 1.1.17 завершает рефакторинг F01–F17: разделение клиентских и серверных сценариев без смены основного пользовательского пути, полный тестовый контур, усиление диагностики и атомарный лимит отчётов. Исправлена клавиатурная доступность окна отчёта. Оплата и новые продуктовые функции не включены.

По сравнению с origin/main в ветке одна новая миграция: 20261020120000_atomic_support_report_submission.sql. Она добавляет server-only RPC для отправки отчётов, не меняя таблицы. Реальный список pending migrations определяется только сверкой с production history и dry run. Обновлённую Edge Function submit-support-report нельзя развёртывать до этой RPC.

## Принятое ограничение доступности

По просьбе владелицы исходные цвета светлой темы возвращены. Ранее измеренные сочетания белого текста на коралловой кнопке (около 2,7:1) и приглушённого текста на светлой карточке (около 3,3:1) не достигают согласованного порога 4,5:1. 16.11.2026 владелица решила оставить цвета и явно принять это ограничение для 1.1.17. Статус — Accepted limitation по AC-3; соответствие порогу не заявляется.

## Ручной rollout владельца

1. Сверить production commit, миграционную историю, текущие функции и настройки; убедиться, что release candidate соответствует согласованному scope.
2. Проверить свежий completed snapshot и checksums. Новый isolated recovery drill по решению владельца не выполняется; отметить NotRun. Восстановимость свежего snapshot и целевой RTO не доказаны.
3. Получить dry run по проверенной operational-процедуре; сверить список, порядок и SQL с миграцией релиза. При drift, неожиданном SQL/lock или отсутствии ожидаемой истории остановиться.
4. Применить только согласованную миграцию по owner-run процедуре. Подтвердить history, наличие RPC, права только service_role, RLS и отсутствие критических ошибок БД. Сделать новый snapshot после изменения схемы и проверить status.
5. Обновить server-only secrets при необходимости через защищённый ввод без значений в чате, документах и аргументах shell; проверить работу после замены. Развернуть Edge Functions из того же candidate commit и проверить логи.
6. Владелец создаёт и проверяет PR. Merge в main допускается после DB postcheck, snapshot и Edge deploy. Если Vercel публикует main автоматически, проверить production deployment SHA, версию 1.1.17, frontend env и сборку. Не перенастраивать BotFather или webhook без изменения URL/секрета; для существующего бота не сбрасывать pending updates.
7. Пройти notes/production-smoke-checklist.md внутри production Telegram: вход, настройки, чтение/история, словарь/повторение, роли, отчёт, версия/buildId и логи. При ошибке остановить релиз и использовать согласованный forward-fix или rollback план.
8. Только после smoke = pass владелец создаёт tag v1.1.17 на фактически работающий production commit и GitHub Release. Зафиксировать результаты ниже.

Команды изменения production БД намеренно не помещены в документ. Общие ограничения: notes/production-deploy-flow.md; миграционный порядок и backup: проектные документы владельца.
