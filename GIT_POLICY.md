# GIT_POLICY.md

## Строгая политика работы агента с Git

### 1) Что агенту запрещено
Агенту запрещено выполнять любые Git-команды, которые изменяют коммиты, ветки, теги, индекс или рабочее дерево.

В том числе запрещены:
- `git commit`
- `git push`
- `git pull`
- `git merge`
- `git rebase`
- `git cherry-pick`
- `git reset` (любой режим)
- `git revert`
- `git tag` (создание/удаление)
- `git stash` (все варианты)
- `git checkout` (переключение веток или откат файлов)
- `git switch`
- `git restore`
- `git clean`
- любые другие команды Git с записью/изменением состояния репозитория

### 2) Что агенту разрешено
Разрешен только read-only доступ к Git для анализа и отчетности.

Разрешенные примеры:
- `git status`
- `git log`
- `git diff`
- `git show`
- `git blame`
- `git branch --show-current`
- `git rev-parse`

### 3) Приоритет правила
- Эта политика имеет приоритет над привычными агентными практиками.
- Если задача пользователя предполагает коммит/пуш/слияние, агент должен остановиться и сообщить, что по политике проекта он выполняет только read-only операции в Git.
- Изменение этой политики возможно только через явное редактирование этого файла пользователем/командой.
