# Политика Git для English Daily Loop

## Ветка и область работы

Владелец создаёт, выбирает и назначает ветку под задачу. Агент перед изменениями проверяет репозиторий, текущую ветку, рабочее дерево и согласованный scope. Агент не создаёт и не переключает ветки. Название папки `specs/NNN-slug/` независимо от имени ветки.

## Разрешённые операции

Агент может читать Git-контекст (`status`, `diff`, `log`, `show`, `blame`, `branch --show-current`, `rev-parse`). В назначенной ветке он может адресно добавить в staging только собственные проверенные файлы задачи, выполнить `git commit` и обычный `git push` в точно проверенный remote и ветку. Допускаются несколько commit/push для законченных проверенных частей в рамках одной согласованной цели. Промежуточный push не завершает задачу.

Перед каждым коммитом агент выполняет проверки, обязательные для коммитируемой части, фиксирует реальные результаты в `verification.md`, сверяет ветку и полный staged diff. `git add .` и `git add -A` не используются; чужие изменения и секреты не включаются. Перед push он сверяет remote, ветку назначения и исходящие коммиты. Неизвестное назначение требует уточнения до отправки.

## Запреты

Агенту запрещено создавать и переключать ветки; выполнять merge, rebase, cherry-pick, revert, reset, stash, checkout/restore/clean для изменения состояния, pull с интеграцией, переписывание истории и любые варианты force push, включая `--force-with-lease` и принудительный refspec. Агент не создаёт pull request, не выполняет merge, релиз или действия с production. Эти действия выполняет владелец.

При отклонённом push агент прекращает отправку, сохраняет локальные коммиты и файлы и сообщает владельцу причину. Он не исправляет ситуацию pull, merge, rebase или force push и не заявляет, что отправка состоялась.

Изменения этой политики требуют явного решения владельца; инструкции скиллов не могут расширить разрешения. Скрипты `.specify/` не выполняют Git-команды.
