## Section Rules

- Write metadata and headings in Russian unless an established technical term is clearer in English.
- Do not duplicate the filename as an H1.
- Omit irrelevant sections instead of filling them with generic text.
- Once a question is resolved, move the decision into the target behavior and remove the obsolete question.
- Verify actual file, function, table, and field names before naming them.
- State explicitly when no package, migration, secret, deployment action, or DB mutation is required.
- Order implementation steps by dependency and keep each step independently verifiable.
- Describe acceptance criteria as observable outcomes. Internal architecture belongs in the technical section.
