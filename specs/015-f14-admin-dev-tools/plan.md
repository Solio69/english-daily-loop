## Выбранная архитектура

`dev-tools/index.ts` остаётся HTTP-оркестратором: CORS, POST, env gate, чтение тела, Telegram auth, поиск пользователя, проверка admin, вызов действия, безопасный ответ. Типизированный разбор запроса выносится в `dev-tools-contract.ts`; предметные DB/RPC-операции — в `dev-tools-actions.ts`. Диспетчеризация по явному `switch` находится рядом с исполнением, без динамического выбора операции по входной строке. Охранные условия проверяются до диспетчеризации. Для теста порядка доступ проверяется через малый flow с подставными зависимостями, который не соединяется с реальной БД.

Клиентский сервис сохраняет контракт вызова. `DevToolsPanel` получает список подписей/иконок из отдельной конфигурации и оставляет существующую структуру; `useAppUserActions` отвечает за ожидание, вызов, обновление профиля и toast. Видимость в `App.tsx` основана на серверной роли профиля, защита endpoint основана на роли в БД. Состояние кнопок и сообщения не меняются.

## Контекст и ограничения

Текущие восемь действий используют существующие таблицы и RPC. Вся SQL-семантика, фильтры по user/date/status, порядок двух удалений чтения и московская учебная дата сохраняются. Нет миграций, RLS/grants, новых пакетов, ручных вызовов dev endpoint и DB mutation команд агента. Серверные тесты используют только моки. Версия пакета — `1.1.14`.
