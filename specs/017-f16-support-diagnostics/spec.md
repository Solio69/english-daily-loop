## Результат и границы

Отчёт отправляется из существующей формы настроек, сохраняется на 30 дней и доступен только серверу. F16 ограничивает сохраняемую диагностику явно разрешёнными событиями и полями, очищает известные секретные шаблоны в строках и делает лимит 5 отчётов за скользящий час атомарным. Форма, сообщения пользователю, роли, retention и прямой доступ к таблице сохраняются. Неизвестный произвольный секрет, не похожий на известные форматы, нельзя гарантированно распознать; предупреждение в форме остаётся.

## Сценарии и критерии

- **AC-1:** Given валидная Telegram `initData` и обязательный комментарий, when пользователь отправляет отчёт, then сервер находит внутренний `user_id`, очищает поля и сохраняет один отчёт; клиент видит прежнее подтверждение и получает report ID/date. Проверка: Deno flow на моках и ручной dev-бот после локальной миграции.
- **AC-2:** Given неверная `initData`, пустой комментарий, ошибка сети или БД, when отправка не удаётся, then отчёт не считается успешным, ответ/логи содержат безопасный код и request ID без raw input, Telegram ID, SQL/provider text. Проверка: Deno/клиентские тесты.
- **AC-3:** Given 5 сохранённых отчётов за предыдущие 60 минут для одного пользователя, when поступает шестой, then RPC возвращает сигнал лимита, запись не создаётся, endpoint отвечает `429 SUPPORT_REPORT_RATE_LIMITED`; другой пользователь не ограничен. Проверка: SQL-контракт, Deno mapping и owner-run локальная проверка.
- **AC-4:** Given одновременные запросы одного пользователя на границе лимита, when RPC исполняются, then row lock сериализует проверку и insert на едином DB timestamp; максимум 5 отчётов сохраняются в скользящем окне. Проверка: ревью SQL-контракта и owner-run локальная конкурентная проверка после миграции.
- **AC-5:** Given event/context/AI diagnostics с неизвестными именами или полями и известными секретными шаблонами в строках, when сервер готовит отчёт, then сохраняются только документированные поля допустимых событий; raw `initData`, bearer/token-подобные строки и прямой Telegram ID удалены. Проверка: тесты санитизации с синтетическими значениями.
- **AC-6:** Given отчёт превышает ограничения, when сервер готовит snapshot, then применяются лимиты длины и количества, общий размер не больше 100 KiB; обязательный комментарий и экран остаются. Проверка: тесты граничных значений.
- **AC-7:** Given новая миграция в snapshot, when recovery validation выполняется read-only, then ожидается server-only RPC с execute только у `service_role`; старые snapshots валидируются по своему migration version. Проверка: backup contract tests.

## Требования

- **FR-001:** HTTP handler выполняет POST guard, Telegram auth, поиск пользователя, подготовку отчёта и ровно один вызов server-only RPC. Прямой `select count` и отдельный `insert` в handler не используются.
- **FR-002:** RPC под `FOR UPDATE` блокировкой строки `public.users` считает отчёты пользователя в интервале `(DB timestamp - 1 hour, DB timestamp]`, вставляет запись с тем же timestamp либо выдаёт стабильный сигнал лимита. Она не принимает Telegram ID, не меняет таблицу и доступна только `service_role`.
- **FR-003:** Серверная схема context, events и AI metadata задаёт whitelist известных полей и допустимых event names. Ограничения количества/размера и формат request ID сохраняются. Клиентская защита дополнительно очищает строки в session buffer; сервер остаётся источником истины.
- **FR-004:** Из любого сохраняемого строкового поля удаляются известные шаблоны Telegram `initData`/hash, bearer, token/key/secret/password и прямой Telegram ID до ограничения длины. Неизвестные поля не сохраняются. Комментарий и current screen проходят ту же обработку.
- **FR-005:** Endpoint не пишет в логи raw DB/provider errors, комментарий, содержимое отчёта или пользовательские идентификаторы; наружу отдаёт прежние безопасные коды ошибок, включая 429.
- **FR-006:** Backup/recovery contract учитывает новую RPC по migration version; документация диагностики и backup обновлена. Агент создаёт миграцию, но не применяет её, не выполняет DB mutation и не запускает production backup/recovery.
- **FR-007:** Нет новых пакетов, UI-дизайна, новых таблиц/полей, изменения 30-дневного retention и новых продуктовых сценариев. Версия пакета для коммита F16 — `1.1.16`.

## Данные, доступ и эксплуатация

Затронута `public.support_reports` только через новую server-only RPC, текущие RLS и запрет доступа `anon`/`authenticated` сохраняются. Миграция `20261020120000_atomic_support_report_submission.sql` нужна до запуска нового Edge Function. Агент не применяет локальную или production миграцию. Владелец применяет локальную миграцию для dev-приёмки; production шаги, новый snapshot и recovery drill выполняет отдельно в рамках выпуска. Команды изменения production БД не передаются без отдельного прямого запроса.
