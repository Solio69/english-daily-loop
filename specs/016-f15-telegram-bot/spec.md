## Результат и границы

Существующий webhook уже разделён на HTTP-обработчик, сценарий сообщений и клиент Telegram API. F15 разделяет Node-конфигурацию бота по ответственности и усиливает проверку единого профиля. Поведение `/start`, `/help`, неизвестной команды, кнопки Mini App, dev-запуска и owner-run production-конфигурации сохраняется. Новые команды, тексты, дизайн, зависимости и действия агента с production-ботом не входят.

## Сценарии и критерии

- **AC-1:** Given корректные dev token, username и HTTPS URL, when запускается конфигурация, then `getMe` проверяет бота до изменяющих вызовов; профиль, private commands, menu и webhook применяются в прежнем порядке, возвращается безопасный status. Проверка: Node-тест на подставном fetch.
- **AC-2:** Given username не совпадает, when запускается configure или delete webhook, then изменяющие вызовы не выполняются. Проверка: Node-тест.
- **AC-3:** Given Telegram API вернул ошибку, timeout или неверный JSON, when клиент обрабатывает ответ, then ошибка содержит безопасный код, статус и при применимости категорию отказа webhook без token, secret и raw provider response. Проверка: Node-тест.
- **AC-4:** Given исходники профиля в Node, Deno и JSON, when запускается тест согласованности, then имя, короткое и полное описание, текст кнопки и обе команды совпадают; PowerShell читает тот же JSON для production. Проверка: тест и ревью.
- **AC-5:** Given секретный заголовок webhook и private message, when бот получает `/start`, `/help` или другую команду, then возвращаются прежние ответы и ссылка Mini App; неподходящий заголовок или неподдерживаемые updates отклоняются/игнорируются. Проверка: Deno-тесты и ручной dev-бот.
- **AC-6:** Given владелец запускает production helper, when требуется token/secret, then ввод скрыт, точный production username проверен до настройки. Агент не запускает helper. Проверка: статический контрактный тест и owner-run при выпуске.

## Требования

- **FR-001:** Node-конфигурация разделена на профиль/построение операций, Telegram API/ошибки и оркестрацию configure/delete. Публичные экспорты `bot-config.mjs`, используемые dev-stack и тестами, совместимы.
- **FR-002:** HTTPS URL не содержит userinfo, webhook secret соответствует действующей длине/алфавиту; конфигурация применяет команды только к private chats и принимает только `message` updates.
- **FR-003:** `configureTelegramBot` и `deleteTelegramWebhook` проверяют username через `getMe` до мутаций. Совпадающие поля профиля не перезаписываются. `dropPendingUpdates` сохраняет существующую семантику.
- **FR-004:** Ошибки клиента и webhook status не раскрывают token/secret/raw provider text. Профиль Node, Deno и JSON проверяется независимо ожидаемыми значениями.
- **FR-005:** Production PowerShell использует профиль JSON и скрытые prompts, не получает секреты через CLI-аргументы; агент не запускает изменение production.
- **FR-006:** Нет миграций, изменения БД, новых пакетов и нового продуктового поведения. Версия пакета для коммита F15 — `1.1.15`.

## Данные, доступ и эксплуатация

Таблицы и RLS не меняются. Webhook остаётся единственным публичным Telegram callback, проверяет секретный заголовок и не использует `initData`, БД и `service_role`. Dev-скрипт использует изолированное локальное окружение; production helper выполняет только владелец. Реальные токены не входят в тесты и документы.
