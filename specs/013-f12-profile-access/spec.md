## Результат и границы

Mini App получает профиль по серверно проверенному Telegram initData. Первый и повторный вход возвращают согласованный снимок пользователя, настроек, подписки и дневного прогресса. Сохранение настроек не теряет уже загруженные метрики. При ошибке начального входа приложение показывает полноэкранное состояние ошибки и повтор, не открывая пользовательские экраны.

В объёме: auth-telegram, save-user-settings, общие серверные операции чтения профиля и расчёта доступа, клиентские сервис/состояние профиля, настройки и регрессия скрытого activate-subscription. Вне объёма: платежи, новые роли/лимиты, изменение дизайна действующих экранов, новые данные/таблицы/RPC, изменение политики доступа.

## Сценарии и критерии

- **US-1, первый вход / AC-1:** Given корректное Telegram initData и отсутствие пользователя, when вызывается auth-telegram, then пользователь создаётся по telegram_user_id, ответ содержит профиль с незаполненными настройками, актуальную роль, подписку и прогресс; клиент показывает действующий сценарий первичной настройки. Проверка: серверный и браузерный тест.
- **US-2, повторный вход / AC-2:** Given существующий пользователь с настройками, when вызывается auth-telegram, then возвращаются сохранённые настройки, роль, подписка и дневной прогресс. Проверка: серверный, браузерный и ручной dev-бот.
- **US-3, сохранение настроек / AC-3:** Given авторизованный пользователь, when он сохраняет допустимые englishLevel и dailyReadingMinutes, then сервер сохраняет настройки, однократно фиксирует завершение первичной настройки и возвращает поля профиля/доступа; клиент сохраняет наиболее актуальные streak, историю и прогресс. Проверка: серверный, компонентный и ручной тест.
- **US-4, роли и лимиты / AC-4:** Given admin, tester или user, when вычисляется доступ, then сервер применяет действующую матрицу: внутренний доступ для admin/tester, для user бесплатный или подписочный уровень с текущими лимитами. Проверка: тест матрицы ролей и лимитов, включая срок подписки.
- **US-5, ошибка входа / AC-5:** Given отсутствующее/некорректное initData или отказ сервера, when завершается начальная попытка, then главная и остальные пользовательские экраны недоступны, показано безопасное сообщение и кнопка повторного входа. Given причина устранена, when пользователь нажимает повтор, then загрузка завершается и открывается обычный сценарий. Проверка: компонентный и браузерный тест.
- **US-6, скрытая подписка / AC-6:** Given выключенные клиентский и серверный флаги подписки, when пользователь открывает приложение или вызывает endpoint, then экран подписки не появляется и сервер отказывает в активации. Проверка: регрессионный тест.
- **US-7, безопасные ошибки / AC-7:** Given неверный ввод, ошибка БД или запрет доступа, when endpoint отвечает отказом, then клиент получает безопасный код/сообщение без SQL, ключей, токенов и raw initData. Проверка: тест контрактов ошибок и ревью логов.

## Требования

- **FR-001:** auth-telegram проверяет Telegram initData на сервере и находит либо создаёт одного пользователя по telegram_user_id; повтор не создаёт дубликат.
- **FR-002:** Успешный ответ auth-telegram сохраняет поля и смысл текущего API: user (id, role, firstName, settingsCompletedAt, firstTextCompletedAt), settings, subscription, homeProgress, streakDays, completedReadingTextCount.
- **FR-003:** save-user-settings принимает только A1/A2/B1/B2 и 3/5/10/15 минут, записывает в user_settings через сервер, не меняет роль и повторно не перезаписывает settings_completed_at; успешный ответ сохраняет текущий контракт.
- **FR-004:** Общий серверный расчёт роли, подписки и лимитов остаётся источником решений для защищённых действий. admin/tester имеют внутренний доступ; user — действующий free/paid доступ. Клиентская роль управляет только отображением.
- **FR-005:** Серверный флаг SUBSCRIPTION_FLOW_ENABLED запрещает активацию при выключенном значении; клиентский флаг скрывает экран. activate_mvp_subscription и ответ активации не меняют семантику.
- **FR-006:** Клиент различает начальную загрузку, успешный профиль и ошибку. До успешного профиля рендерятся только загрузка либо полноэкранная ошибка с повтором; повтор не запускает параллельные запросы.
- **FR-007:** Сохранение настроек применяет серверные user/settings/subscription к текущему профилю. Для homeProgress используется серверный snapshot, если клиентский прогресс не менялся во время запроса; если менялся, сохраняется более новое клиентское состояние. Streak и счётчик истории, отсутствующие в ответе сохранения, берутся из текущего профиля.
- **FR-008:** Ошибка позднего обновления профиля оставляет последний успешный снимок и показывает безопасную ошибку; смена учебной даты по действующей московской границе сохраняется.
- **FR-009:** Клиентские ответы не содержат SQL-детали; ответы и логи не содержат raw initData, bot token или service role key. Внутренние ошибки БД остаются только в доверенных серверных логах.

## Данные, доступ и эксплуатация

Используются существующие public.users, public.user_settings, public.user_subscriptions, таблицы прогресса чтения/словаря и server-only RPC. Клиент не пишет в защищённые таблицы напрямую. RLS и grants сохраняются; миграций и изменения данных агентом нет. SUPABASE_SERVICE_ROLE_KEY и TELEGRAM_BOT_TOKEN остаются только в Edge Functions. Скрытый subscription-flow не включается.
