## Результат и границы

Релизная ветка даёт проверяемый кандидат для обновления работающего production. Вся существующая функциональность чтения, словаря, ролей, бота и отчётов сохраняется. F17 объединяет автоматическую регрессию, выборочную ручную проверку критических сценариев в Telegram, обзор доступности и безопасности, измерение сборки и релизную документацию.

Новые продуктовые функции, изменение модели данных, самостоятельные действия агента с production, PR, merge и публикация не входят. Новых пакетов нет. Найденный дефект исправляется в F17 только если необходим для выпуска и не меняет согласованное поведение; существенное новое решение возвращается владельцу.

## Сценарии и критерии

- **AC-1, автоматическая регрессия:** typecheck, lint, format, styles, Node/Vitest, Playwright, Deno и production build проходят на финальном кандидате. Каждый результат и непроведённая проверка имеют фактический статус в verification.md. GitHub Actions проверяется после owner-run push/PR.
- **AC-2, реальный Telegram:** владелец подтверждает в dev-боте команды /start, /help и открытие Mini App; auth, настройку, генерацию и завершение текста, словарь и повторение, отчёт об ошибке; видимость dev tools для admin и обычной роли. Отказы и лимит отчётов проверяются по доступным сценариям и отмечаются отдельно. Формулировка «базово работает» не заменяет отметки конкретных сценариев.
- **AC-3, доступность:** основные экраны и действия доступны с клавиатуры, фокус виден и не теряется при переходах/модальных окнах, интерактивные элементы имеют понятные названия; светлая и тёмная темы, мобильный viewport и состояния ошибки не скрывают важные действия. Проверенные сочетания обычного текста и ключевых кнопок в светлой теме должны иметь контраст не ниже 4,5:1. Найденные критические дефекты устраняются или блокируют выпуск.
**Исключение AC-3 для 1.1.17:** 16.11.2026 владелица решила сохранить исходную палитру и явно принять обнаруженный контраст ниже 4,5:1. Это известное ограничение выпуска, а не успешная проверка доступности. Остальные требования AC-3 сохраняются; для следующих изменений цветовые сочетания пересматриваются отдельно.

- **AC-4, безопасность и совместимость:** server-side Telegram auth, ограничения ролей, RLS/grants и server-only секреты остаются закрытыми; отчёты и логи не содержат raw initData/ключей. Миграция F16 только добавляет RPC и применяется владельцем до обновлённой Edge Function; текущий production SHA и миграции сверяются перед rollout. Runtime DB-проверки, требующие изменения данных, выполняет владелец.
- **AC-5, сборка:** обычная production-сборка и отдельная Telegram dev-сборка проходят без ошибки; размеры JS/CSS зафиксированы. Предупреждение о чанке выше 500 КБ оценивается по замеру и влиянию, а не скрывается поднятием порога без основания. Telegram dev-сборка не перезаписывается агентом при работающем dev-stack.
- **AC-6, релизные артефакты:** package.json, currentRelease и CHANGELOG согласованы на версии 1.1.17 и фактической дате выпуска; release:check проходит. Пользовательские заметки кратки, техническая история и инструкция обновления существующего production актуальны. Устаревшие ссылки на work/agents исправлены.
- **AC-7, передача и production smoke:** владелец получает порядок ручного обновления: подтверждение production SHA и истории миграций, свежий snapshot, dry run и применение согласованной миграции, postcheck, Edge Functions, PR/merge и frontend, затем smoke в production Telegram. Tag/GitHub Release только после успешного smoke. Агент не отмечает owner-run шаги успешными без результата.

## Данные, безопасность и исключение

По сравнению с main в ветке есть одна новая миграция, создающая server-only RPC submit_support_report. Фактический состав pending миграций для production пока неизвестен. Она не меняет таблицы и должна предшествовать новой реализации Edge Function. Точный список pending миграций определяется только по фактической production migration history и dry run; исходный код не заменяет эту проверку.

Новый snapshot от 16.11.2026 прошёл проверку checksums. Владелец прямо решил пропустить isolated recovery drill для этого выпуска, хотя действующий runbook требует его. В verification.md статус drill — NotRun и фиксируется риск: восстановимость свежего snapshot и RTO не подтверждены. Это решение не превращает drill в Passed.

## Приёмка и полномочия

Владелец проверяет финальный кандидат и выполняет ручные production-операции. Агент готовит документы, код и проверки без production access; не выполняет миграции, backup, restore, deploy, PR, merge, release, commit или push без отдельного указания в текущей сессии. Дата в релизных артефактах указывается по фактическому дню публикации; до его подтверждения release:check может оставаться NotRun/Blocked.
