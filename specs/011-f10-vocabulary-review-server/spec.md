## Результат и границы

`get-vocabulary-review-state` и `review-vocabulary-word` разделены на HTTP/auth, предметные сценарии чтения/действия и RPC-адаптеры. Общие типы и проверка ответов БД имеют ясного владельца. Действующая шкала интервалов, очередь, обязательные/дополнительные слова, счётчики и дата учебного дня сохраняются. SQL, схема, права, клиентский экран, зависимости и миграции не входят.

## Пользовательские сценарии и критерии

- **US-1:** Пользователь видит актуальную очередь и отвечает по карточке, после чего получает следующий шаг и прогресс.
- **AC-1:** Snapshot готовой очереди возвращает текущую карточку, доступные действия, обязательные/дополнительные счётчики и marker в прежнем формате. Пустой план обрабатывается через `get_or_create_vocabulary_review_state`, включая атомарную фиксацию completion-marker.
- **AC-2:** `forgot`, `same_step`, `next_step`, `jump_step` сохраняют действующие интервалы и переход `6_months` → `learned`; сервер передаёт действие в `review_vocabulary_word` без расчёта нового состояния на Edge.
- **AC-3:** Ошибки несуществующего, неготового и изученного слова отображаются действующими HTTP статусами/кодами. RPC сериализует конкурентные запросы; повторный допустимый ответ может примениться ещё раз, поскольку request ID и идемпотентного claim здесь нет. Валидация `wordId`/`action` и форма успешного ответа сохраняются.
- **AC-4:** Учебная граница 05:00 Europe/Moscow и дата, связанная с одним DB timestamp mutation, остаются в SQL. Передаваемая Edge дата остаётся совместимым аргументом RPC. Telegram auth и server-only доступ обязательны.

## Функциональные требования

- **FR-001:** Сохранить POST/CORS, Telegram auth, owner scoping, вход и публичные ответы обоих endpoint.
- **FR-002:** Выделить независимые сервисы snapshot и review action; reuse только полностью совпадающих предметных правил.
- **FR-003:** Проверять данные RPC перед отображением; при повреждённом ответе возвращать безопасную серверную ошибку.
- **FR-004:** Оставить lock, дату mutation, переходы и completion-marker в действующих SQL RPC без изменений прав или схемы.

## Данные, права и проверки

Используются действующие `get_or_create_vocabulary_review_state`, `review_vocabulary_word` и shared review helpers. Read endpoint может записать marker пустого плана внутри RPC; агент не запускает его против реальной БД. AC-1–4 проверяются Deno тестами с подставным RPC и статическим SQL contract review. Mock не доказывает фактические DB-конкурентность и запись marker. Обязательные gates: test:edge, test, test:e2e, typecheck, lint, format:check, lint:styles, build, code/security review и staged diff. Владелец проверяет ответ в dev-боте.
