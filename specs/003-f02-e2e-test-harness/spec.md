## Результат и границы

Проект получает быстрые браузерные сценарии с подставными Telegram/API, Deno-тесты Edge helpers без сети и отдельную проверку local DB/RLS для запуска владельцем. Проверки не используют реальные токены, AI или production. Локальная БД остаётся текущей рабочей; общий reset и изменение чужих записей исключены. Агент не выполняет DB-mutating проверки. Продуктовый UI/API в F02 не меняется.

## Сценарии и критерии

- **AC-1:** Given чистый checkout, when агент запускает Playwright с локальным web server и моками, then успешный bootstrap показывает главный экран, а отказ auth — понятную ошибку; ни один запрос не доходит до реального Supabase/OpenRouter.
- **AC-2:** Given Edge shared helpers, when запускается Deno test, then основные успешные и ошибочные HTTP-контракты проверяются без БД, секретов и сети.
- **AC-3:** Given текущий local Supabase на ожидаемом адресе, when владелец запускает DB/RLS-проверку, then тест проверяет закрытость защищённых таблиц для anon/authenticated и откат всех тестовых записей.
- **AC-4:** Given неожиданный DB target, отсутствующий локальный стек или уже занятый fixture ID, when владелец пытается запустить DB-проверку, then она останавливается до записи.
- **AC-5:** Given push/PR, when запускается CI, then Playwright с моками и Deno входят в проверку без БД и секретов; local DB/RLS-команда в CI не вызывается.

## Требования

- **FR-001:** Браузерные тесты используют `@playwright/test`, фиксированный viewport и Telegram WebApp mock до загрузки приложения; API mocks дают стабильные ответы успеха и ошибки.
- **FR-002:** Конфигурация браузерных тестов запускает приложение локально с фиктивными Supabase URL/anon key и блокирует любую сеть вне локального web server.
- **FR-003:** Deno-тесты покрывают выбранные shared helpers с независимыми ожиданиями и не требуют runtime secrets.
- **FR-004:** DB/RLS сценарий использует только текущий local Supabase, выделенный fixture ID/Telegram ID, транзакцию с rollback и проверку точной цели; не выполняет reset, миграции или общий cleanup.
- **FR-005:** Запуск DB/RLS принадлежит владельцу после подготовки кода F01–F04. До результата AC-3/4 имеет статус NotRun и F02 не коммитится как завершённая; затем один коммит F02 включает спецификацию, код, проверки и версию 1.1.2.
- **FR-006:** CI включает browser/Deno, оставляет DB/RLS owner-run, не содержит production credentials.

## Данные, доступ и эксплуатация

Новые продуктовые миграции не создаются. Реальные персональные данные не используются. DB test при ручном запуске в текущем локальном стеке должен откатить фикстуру при успехе и ошибке. Продуктовые права/RLS не ослабляются. Браузерные и Deno-тесты полностью подставные.

## Проверка

AC-1: Playwright success/error и сетевой guard; AC-2: `deno test` по отдельному набору; AC-3/4: одна owner-run команда и сохранённый вывод после всех четырёх фич; AC-5: локальная проверка workflow и удалённый CI после push. До ручного прогона DB-пункты NotRun.

## Открытые вопросы

Существенных продуктовых вопросов нет. Точный синтаксис безопасного DB-теста и расположение Deno CLI определяются в плане на основе текущего окружения и действующего Supabase CLI.
