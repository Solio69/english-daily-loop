## Решение и основания

Сохранить текущие сетевые endpoints и React без новых пакетов. readingService остаётся единственной клиентской границей Edge Functions и содержит перевод ответа генерации в ReadingText. Предметный hook/controller управляет загрузкой, генерацией, восстановлением после неопределённого результата и завершением. Действующий useReadingPosition остаётся отдельным владельцем scroll/position synchronization. Состояние выбранного слова и его mutation-операции выделяются отдельно, но продолжат использовать vocabularyService; правила F08 не переносятся в клиент чтения. ReadingScreen соединяет контроллеры и компоненты, не выполняя сетевые вызовы напрямую.

Выбирать минимальное количество хуков по реальным обязанностям, не создавать глобальное состояние или новый state-management framework. При необходимости reducer можно использовать локально для проверяемых переходов; решение основывать на тестируемости и отсутствии дублирующих состояний. Поля внешнего ответа проверяются на сервисной границе, не доверяя TypeScript generic как runtime-валидации.

## Контекст

Основные файлы: src/screens/ReadingScreen.tsx, src/services/readingService.ts, src/hooks/useReadingFlow.ts, src/hooks/useReadingWordActions.ts, src/hooks/useReadingPosition.ts, src/hooks/useAppUserActions.ts, src/types/reading.ts, src/components/reading/*. ReadingScreen соединяет сценарий, позицию и визуальные компоненты. После неясного результата генерации клиент перечитывает состояние; retryUnknownGenerationOutcome использует тот же request ID. Завершение приходит через App callback и обновляет домашний прогресс. MaterialsScreen и общий App shell находятся вне границы F07.
