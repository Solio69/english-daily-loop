## Результат и границы

Клиентское чтение сохраняет действующий внешний вид, тексты, навигацию и пользовательские правила. Сетевой сервис, состояние сценария и отображение разделены; экран остаётся композицией элементов чтения. Фича включает ReadingScreen, readingService, предметные типы, связанные хуки/утилиты и проверки. Серверные контракты F05/F06 уже готовы. Серверные операции словаря F08, материалы и общий App shell F13 не рефакторятся.

## Сценарии и критерии

- **US-1:** Пользователь открывает, генерирует, читает и завершает текст в привычном интерфейсе.
- **AC-1:** Given первый или повторный вход, when открыт экран чтения, then загружается get-reading-state; текст, позиция, счётчик попыток, дневной completion и сохранённые слова отображаются как в текущем приложении. Пустое и ошибочное состояние сохраняют прежний вид и доступные действия.
- **AC-2:** Given свободная попытка, when пользователь запускает генерацию, then одна операция находится в полёте, новый текст и счётчики отображаются после успешного ответа, а видимый домашний статус обновляется.
- **AC-3:** Given результат генерации неизвестен из-за сетевой ошибки, when выполняется действующий повтор, then используется тот же request ID; после ошибки экран запрашивает серверное состояние и показывает сохранённый новый текст, если он появился, иначе прежний текст и безопасное сообщение. Дублирующая попытка не инициируется.
- **AC-4:** Given активный текст с сохранённой позицией, when экран открыт повторно, then отображение возвращается к соответствующему абзацу; прокрутка и действие наверх сохраняют позицию через существующий сервис, ошибка сохранения показывает возможность повтора.
- **AC-5:** Given слово в текущем тексте, when пользователь сохраняет его или удаляет допустимое pending-слово, then индексы и доступное действие на экране соответствуют серверному ответу; конфликт готовой карточки/отсутствующего источника обновляет состояние через get-reading-state без чужих изменений.
- **AC-6:** Given активный текст, when пользователь завершает чтение, then вызов server endpoint завершается до локального сброса текста и перехода; домашний прогресс и счётчики обновляются через существующий App callback.
- **AC-7:** Given светлая или тёмная тема и мобильный Telegram viewport, when проходят сценарии чтения, then компоненты, тексты, навигация, управление с клавиатуры и внешний вид остаются в рамках текущей дизайн-системы без визуального редизайна.

## Требования

- **FR-001:** Сохранить действующие endpoints, форму их запросов/ответов, клиентский retry одного request ID и server recovery.
- **FR-002:** Оставить сервер источником истины при повторном входе, неясном результате генерации и конфликте словаря.
- **FR-003:** Отделить типизированный сетевой API от управления состоянием; ReadingScreen отвечает за композицию и UI, предметные переходы имеют тестируемого владельца.
- **FR-004:** Сохранить синхронизацию позиции, дебаунс/повтор, сброс наверх, действия со словами и завершение без изменения пользовательской логики.
- **FR-005:** Сохранить дизайн-систему, тексты, маршруты, loading/empty/error состояния и доступность.
- **FR-006:** Не менять server-side словарь, материалы, App shell, настройки и схему БД за пределами узкого взаимодействия с чтением.

## Данные, доступ и эксплуатация

Клиент продолжает использовать Telegram initData только для server-side validation в Edge Functions. Секреты и service_role в клиент не попадают. Используются существующие API и типы чтения; миграций и новых пакетов нет. Деплой/выпуск остаётся у владельца.
