## Результат и границы

Репозиторий предоставляет быстрые и воспроизводимые проверки до реализации следующих фич. Существующие Node-тесты продолжают запускаться. В F01 входят Vitest с jsdom и React Testing Library, отдельные проверки типов, ESLint, Prettier, Stylelint и сборки, а также CI без секретов. Playwright, Deno и DB/RLS-контур относятся к F02. Пользовательское поведение, данные, API и production не меняются. Массовое форматирование и перенос всех старых тестов не входят.

## Сценарии и критерии

- **US-1:** Разработчик может отдельно запустить каждый вид проверки и получить ненулевой код выхода при дефекте.
- **AC-1:** Given чистый checkout с установленными зависимостями, when запускаются typecheck, lint, format:check, lint:styles, test и build, then все команды завершаются успешно и не требуют production-секретов.
- **AC-2:** Given прежний набор Node-тестов, when запускается основная тестовая команда, then эти тесты продолжают выполняться вместе с новым быстрым контуром.
- **AC-3:** Given компонент с видимым пользовательским поведением, when запускается компонентный тест, then React Testing Library проверяет результат взаимодействия в jsdom.
- **AC-4:** Given намеренное нарушение правила в контролируемом тестовом файле, when запускается соответствующая проверка, then она возвращает ошибку. Файл затем восстанавливается без изменения исходников приложения.
- **AC-5:** Given push в назначенную ветку или PR, when запускается CI, then те же доступные проверки выполняются без DB и без секретов.

## Требования

- **FR-001:** `package.json` разделяет проверку типов, ESLint, Prettier, Stylelint, Node-тесты, Vitest и сборку; `pnpm test` не теряет существующие тесты.
- **FR-002:** Vitest использует jsdom для React-компонентов и Testing Library; тесты проверяют наблюдаемое поведение, а не текст реализации.
- **FR-003:** Конфигурации ESLint, Prettier и Stylelint соответствуют React, TypeScript и Tailwind CSS v4. Формат новых/затронутых файлов: 2 пробела, одинарные кавычки, без завершающих `;`, LF.
- **FR-004:** Начальный охват и исключения проверок явно описаны; новый файл в охваченной области не скрывается общим исключением. Исторический код не форматируется массово.
- **FR-005:** CI запускает доступные проверки без credentials, DB и production-секретов, используя lockfile.
- **FR-006:** В `pnpm-lock.yaml` фиксируются только согласованные dev-инструменты и необходимые транзитивные зависимости без массового обновления продуктовых пакетов.
