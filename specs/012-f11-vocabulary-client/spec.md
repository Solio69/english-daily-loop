## Результат и границы

Клиентский API словаря, состояние вкладки материалов, состояние повторения и отображение разделены по ответственности. Входят `vocabularyService`, `src/types/vocabulary.ts`, `useVocabularyMaterials`, `VocabularyTab`, `VocabularyScreen` и связанные предметные компоненты/helpers. Общая оболочка, навигация `MaterialsScreen` и история чтения — F13. Дизайн, тексты, маршруты, действия, основные сценарии, server API и скрытый approval-flow сохраняются. Новых пакетов, глобального state manager и миграций нет.

## Пользовательские сценарии и критерии

- **US-1:** Пользователь видит сохранённые слова, подготавливает карточки и проходит дневное повторение.
- **AC-1:** Вкладка словаря показывает прежние pending/ready counts и списки; после подготовки и повторного открытия данные обновляются из сервера.
- **AC-2:** Экран «Слова» отображает актуальную карточку, ответ, следующий шаг и прогресс; повторный клик/запрос во время сохранения блокируется.
- **AC-3:** Если сервер сохранил ответ, а последующая загрузка состояния не удалась, старая карточка не допускает нового ответа; пользователь может безопасно повторить загрузку.
- **AC-4:** Пустой план, ошибки, возврат между экранами и скрытый approval-flow сохраняют действующие состояния и навигацию.
- **AC-5:** Мобильный вид в светлой/тёмной теме, JSX/CSS/копирайт соответствуют текущему дизайну; внешние ответы с повреждёнными важными полями дают безопасную ошибку на границе сервиса.

## Функциональные требования

- **FR-001:** Разделить API-адаптеры, состояние review/materials и композицию UI без изменения маршрутов и server API.
- **FR-002:** Проверять значимые поля внешнего ответа до использования; сохранять существующие корректные ответы и ошибки.
- **FR-003:** Сохранить блокировку двойного ответа и защиту от устаревшей карточки после успешной mutation/неудачного refresh.
- **FR-004:** Сохранить функциональность вкладки словаря в «Моих материалах»; оболочку MaterialsScreen не переписывать.
- **FR-005:** Сохранить дизайн, текст и отключённый approval-flow.

## Данные, доступ и проверки

Клиент обращается только к действующим Edge Functions с Telegram initData; прямой записи в защищённые таблицы нет. AC-1–5 проверяются компонентными и браузерными тестами, визуальным review и ручным dev-ботом владельца. Сквозной сценарий: сохранить слово → подготовить карточку → открыть словарь → повторить → повторно открыть. Обязательные gates: test:edge, test, test:e2e, typecheck, lint, format:check, lint:styles, build, code/security review и staged diff.
